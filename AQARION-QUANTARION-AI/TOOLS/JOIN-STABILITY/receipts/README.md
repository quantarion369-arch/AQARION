# JOIN-STABILITY Reproduction Receipts

Receipts are execution records, not claims inferred from source code.

## Required record

Each release-candidate run should record:

- package ID and version;
- UTC start and completion time;
- repository URL;
- tested Git revision;
- declared source baseline;
- command line;
- Python version;
- Lean version and mathlib revision, if Lean was run;
- exit code for each command;
- stdout and stderr;
- SHA-256 for the manifest, registries, scripts, proof document,
  and Lean source;
- final result and the exact scope of that result.

## Result vocabulary

- PASS: the named command completed successfully.
- FAIL: the named command failed.
- BLOCKED: a required prerequisite was unavailable or unverified.
- NOT_RUN: the command was not executed.

Do not infer PASS from a file existing.
Do not infer theorem verification from a passing Python script.
Do not infer Lean verification from a theorem statement or a file
containing `sorry`.

## Current status

This README is a receipt policy. It is not itself a run receipt.
Actual reproduction logs and status files must be generated by
executing reproduce.sh in the intended checkout.

## Checked reproduction format

`reproduce.sh` delegates to the package-specific `reproduction.py`.
A complete command run requires a clean tracked working tree and index,
an externally supplied exact tested revision, tracked package inputs,
and an ancestor source baseline.

Each run creates a unique `AQARION-join-stability-*` directory in the
user's home directory, outside the repository. It contains separate
per-command stdout/stderr files, a combined `reproduction.log`, and an
atomically published `receipt.json`. Cross-stream ordering in the
combined log follows pipe readiness; the separate streams are retained.

`receipt.json` is the authoritative final status record. A `.tmp` file,
an output directory, or a producer PASS line is not a completed receipt.
A failed log or receipt write causes nonzero execution. The
REPRODUCTION_STATUS marker now points to the JSON receipt.

The receipt records source hashes before and after execution, command
arguments and exits, timestamps, Python version, output hashes, revision,
baseline, result scope, and Lean NOT_RUN/OPEN. Promotion is not changed.

`test_reproduction.py` uses isolated synthetic Git fixtures. Its passing
tests do not establish that the real finite audit was reproduced.
